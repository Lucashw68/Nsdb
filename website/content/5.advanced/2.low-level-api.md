description: Drop to a dynamic response-object adapter when generated models are not the right fit.

---

`useSupabaseApi()` is the database escape hatch. It accepts runtime table names and returns discriminated response objects instead of rejecting Supabase failures.

```ts
const api = useSupabaseApi()

const result = await api.all('exampleTable', {
  where: { active: true },
  orderBy: 'created_at',
  orderDirection: 'desc',
  limit: 20,
})

if (result.success) {
  console.log(result.data, result.count)
} else {
  console.error(result.error)
}
```

## Canonical methods

| Method | Purpose |
| --- | --- |
| `all` | Query a row collection and exact count. |
| `getById` | Read one row by `id` or a custom key. |
| `create` | Insert and return a row. |
| `update` | Update by `id` or a custom key. |
| `remove` | Delete by `id` or a custom key. |
| `upsert` | Insert or update, optionally with `onConflict`. |
| `count` | Count all rows or one equality filter. |
| `findOne` | Return one row matching list options. |

Use generated models for normal component code: their `Row`/`Insert`/`Update` types and throwing contract are simpler. Use Supabase JS directly when you need an operation outside this adapter.
