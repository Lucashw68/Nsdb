---
title: Column Exposure
description: Generate a smaller, safer client surface without confusing metadata with authorization.
badge: Advanced
---

Configure per-column behavior under `tables.columns`:

```ts [nsdb.config.ts]
export default {
  tables: {
    include: ['profiles'],
    columns: {
      profiles: {
        email: { editable: false },
        avatar_url: { hidden: true },
        internal_note: { serverOnly: true },
      },
    },
  },
}
```

## Exact semantics

| Policy | Meaning |
| --- | --- |
| `selectable` | May appear in generated row types, default selects, and list metadata. |
| `editable` | Allowed in generated create/update UI payloads. |
| `readonly` | A semantic result: selectable but never sent by generic mutations or forms. Configure with `editable: false`. |
| `hidden` | Excluded from generic UI but still usable explicitly in code when selectable. |
| `serverOnly` | Non-selectable, non-editable, hidden, and omitted from client-generated schema/model artifacts. |

Contradictory `serverOnly` policies fail validation instead of relying on precedence rules.

::callout{type="danger" title="Not authorization"}
Client exposure settings never replace RLS. They minimize the client surface and guide generic UI; PostgreSQL policies must still reject unauthorized access.
::
