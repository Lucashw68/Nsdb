Self-hosted generation can use a PostgreSQL connection URL instead of a Supabase project ID.

```bash [.env]
SUPABASE_DB_URL=postgresql://postgres:password@localhost:5432/postgres
```

```ts [nsdb.config.ts]
import type { NsdbConfig } from '@lucashw68/nsdb/types/config'

export default {
  supabase: {
    schema: 'public',
    dbUrl: process.env.SUPABASE_DB_URL,
    linked: false,
  },
} satisfies NsdbConfig
```

Then generate normally:

```bash
npx nsdb generate:all
```

## Why the database URL matters

Direct PostgreSQL access lets NSDB query `pg_catalog` for exact primary keys, unique and foreign-key constraints, SQL types, defaults, nullability, enums, identity columns, and generated columns.

Without it, the TypeScript fallback is less precise and generation prints a warning. Keep the URL in local or CI environment variables; never commit credentials.
