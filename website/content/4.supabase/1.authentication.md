NSDB does not implement authentication itself. It relies on the Nuxt Supabase module, [`@nuxtjs/supabase`](https://supabase.nuxtjs.org/), to install the Supabase client and expose the authenticated user inside Nuxt.

## Install and register Nuxt Supabase

```bash
npx nuxi@latest module add supabase
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@lucashw68/nsdb',
    '@nuxtjs/supabase',
  ],
})
```

The module provides the `useSupabaseClient()` and `useSupabaseUser()` composables used by your application and by NSDB's identity-aware runtime. Configure login, redirects, cookies, and sessions with Nuxt Supabase—not with NSDB. See the [Nuxt Supabase documentation](https://supabase.nuxtjs.org/) and its dedicated [authentication guide](https://supabase.nuxtjs.org/getting-started/authentication).

## Sign in with Nuxt Supabase

Authentication calls go through the Supabase client supplied by `@nuxtjs/supabase`:

```vue [app/pages/login.vue]
<script setup lang="ts">
const client = useSupabaseClient()
const email = ref('')

async function signIn() {
  const { error } = await client.auth.signInWithOtp({
    email: email.value,
  })

  if (error) throw error
}
</script>
```

NSDB does not receive credentials and does not add a second authentication API.

## How NSDB uses the authenticated identity

NSDB observes the current identity for three data-safety concerns:

- direct and store rows are cleared when identity changes;
- persisted store data remains quarantined until the restored identity matches;
- realtime channels close before switching scope and may reopen only for an explicitly requested subscription.

```ts
const user = useSupabaseUser()
const client = useSupabaseClient()
const exampleTable = useExampleTable({ store: true })
```

`useSupabaseUser()` comes from `@nuxtjs/supabase`. NSDB observes that same user when isolating model state, persisted rows, and Realtime subscriptions.

Authentication proves identity. RLS still decides which rows that identity can read or mutate.

::callout{type="tip" title="Test real identity transitions"}
Test anonymous, user A, logout, and user B flows against a disposable local Supabase stack. A new identity must never observe previous rows, including during persisted-state hydration.
::
