---
title: Relations
description: Include generated relation aliases for common reads and use raw selects as an escape hatch.
---

Use generated aliases instead of writing PostgREST select strings for common cases:

```ts
const posts = await usePosts().fetch({
  include: ['author', 'tags'],
})
```

Relation metadata is based on database constraints, not only table names. It preserves constraint names, ordered columns, direction, nullability, and stable aliases.

## Supported read shapes

- simple foreign keys;
- inverse relations;
- multiple foreign keys to the same table;
- self-references such as `parent` and `children`;
- classic two-foreign-key many-to-many join tables;
- represented composite foreign keys.

For a relation the generated catalog does not express, use the raw `select` option:

```ts
await posts.fetch({
  select: '*, author:profiles(id, display_name)',
})
```

## Many-to-many limits

Many-to-many relations have read support. Automatic generic editing is not provided. Use a dedicated application component or field/full-form slot and mutate the join table explicitly.

Payload-bearing join tables are not hidden. Generated CRUD also rejects tables with no primary key or a composite primary key until a typed key-object API exists.
