---
title: Migrating to 1.0
description: Replace pre-RC aliases with the single stable NSDB vocabulary and regenerate models.
---

The compatibility window ended in the `1.0.0-rc.1` source candidate. When `1.0.0-rc.2` is published, install it, regenerate models, and apply these mechanical changes.

## Generated models

| Before | Now |
| --- | --- |
| `model.sync()` | `model.subscribe()` |
| `model.fetch({ force: true })` | `model.refresh()` |
| `model.find({ where })` | `model.fetch({ where })` |
| `model.new()` | `model.createDraft()` |
| `model.all(options)` | `model.fetch(options)` |
| `model.get(id)` | `model.getById(id)` |
| `model.edit(id, data)` | `model.update(id, data)` |
| `model.delete(id)` | `model.remove(id)` |
| `listRef.reload()` | `listRef.refresh()` |

## Low-level API

| Before | Now |
| --- | --- |
| `api.show(resource, id)` | `api.getById(resource, id)` |
| `api.destroy(resource, id)` | `api.remove(resource, id)` |
| `api.find(resource, options)` | `api.all(resource, options)` |
| `api.allByProperty(resource, key, value)` | `api.all(resource, { where: { [key]: value } })` |
| `api.showByProperty(resource, key, value)` | `api.getById(resource, value, { key })` |
| `api.updateByProperty(resource, key, value, data)` | `api.update(resource, value, data, { key })` |
| `api.deleteByProperty(resource, key, value)` | `api.remove(resource, value, { key })` |
| positional `api.all(resource, select, ...)` | `api.all(resource, options)` |

## Package paths

| Before | Now |
| --- | --- |
| `@lucashw68/nsdb/useSupabaseModels` | `@lucashw68/nsdb/useSupabaseModel` |
| `@lucashw68/nsdb/useNsdbSchemas` | `@lucashw68/nsdb/useNsdbSchema` |
| `@lucashw68/nsdb/createSingletonDbStore` | `@lucashw68/nsdb/createSingletonStore` |

## Complete the migration

```bash
npm install @lucashw68/nsdb@next
npx nsdb generate:all
```

Then typecheck and test the consumer application. Canonical CRUD return values, model promise rejection, and reactive `error` behavior remain unchanged.
