---
title: Component Customization
description: Keep automatic behavior and replace only the rendering your application owns.
---

NSDB components provide semantic behavior, not a design system. Style them through regular CSS, the `classes` prop, `unstyled`, or stable slots.

## Replace only what you need

```vue
<NsdbList model="exampleTable">
  <template #card="{ row }">
    <ExampleTableCard :entry="row" />
  </template>
</NsdbList>
```

```vue
<NsdbForm model="profiles">
  <template #field-avatar_url="slotProps">
    <AvatarPicker
      :model-value="slotProps.value"
      @update:model-value="slotProps.update"
    />
  </template>
</NsdbForm>
```

The principle is simple: automatic by default, explicit where the field or business workflow is specific.

## Advanced fields

Use field slots for file uploads, rich JSON editors, address pickers, or business-specific validation. NSDB does not pretend that a Storage upload and a PostgreSQL mutation form one atomic transaction.

Many-to-many editing is also explicit. Read the join-table state through generated relations, then use a slot or dedicated application component for multi-step changes.
