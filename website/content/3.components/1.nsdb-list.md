---
title: NsdbList
description: Render a semantic, searchable table or card list from generated model metadata.
---

`NsdbList` resolves a generated model through the registry and loads it on client mount.

```vue
<NsdbList model="exampleTable" />
```

## Add search

```vue
<NsdbList
  model="exampleTable"
  searchable
  :search-columns="['title']"
/>
```

Search is debounced, resets pagination, and runs on the server through the model query.

## Share state through Pinia

```vue
<NsdbList
  model="exampleTable"
  store
  searchable
  :search-columns="['title']"
  :page-size="20"
/>
```

Store mode shares the collection with other store-backed handles and components for the same table.

## Customize cells

```vue
<NsdbList model="exampleTable">
  <template #cell="{ column, row, value }">
    <strong v-if="column.key === 'title'">{{ row.title }}</strong>
    <span v-else>{{ value }}</span>
  </template>
</NsdbList>
```

The stable slot families include `header`, `toolbar`, `error`, `loading`, `empty`, `cards`, `card`, `thead`, `th`, `body`, `cell`, `footer`, `pagination`, and a full default controller slot.

## Core props

| Prop | Purpose |
| --- | --- |
| `model` | Generated model registry name. |
| `store` | Use the shared Pinia-backed handle. |
| `query` | Base model query. |
| `columns` | Explicit column definitions. |
| `searchable` / `searchColumns` | Enable server-side text search. |
| `pageSize` | Enable page-based limit and offset. |
| `filters` | Component convenience merged into `query.where`. |
| `sortBy` / `sortDirection` | Initial server-side ordering. |
| `variant` | `'table'` or `'cards'`. |

The component ref and default controller expose `refresh()`. Inferred columns honor `selectable`, `hidden`, and `serverOnly` metadata.

::callout{type="note" title="SSR data"}
Automatic component loading begins on client mount to avoid hydration races. For SSR, call a store-backed generated model inside `useAsyncData`; transferred Pinia state can then be reused by the list.
::
