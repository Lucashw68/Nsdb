---
title: NsdbForm
description: Create and edit rows from generated schema metadata while keeping custom fields explicit.
---

The minimal form creates a row using generated insert metadata:

```vue
<NsdbForm model="exampleTable" />
```

Pass an ID to edit an existing row:

```vue
<NsdbForm model="exampleTable" :id="entryId" />
```

## Share model state

```vue
<NsdbForm model="exampleTable" store />
```

Successful store-backed mutations become visible to a store-backed `NsdbList` for the same model.

## Handle events

```vue
<NsdbForm
  model="exampleTable"
  @saved="onSaved"
  @error="onError"
/>
```

Create success emits `created`, then `saved`. Update success emits `updated`, then `saved`. Failures emit only `error`, retain the current values, and can be retried.

## Override one field

```vue
<NsdbForm model="profiles">
  <template #field-avatar_url="{ value, update, error }">
    <AvatarPicker
      :model-value="value"
      :error="error"
      @update:model-value="update"
    />
  </template>
</NsdbForm>
```

Field slots receive `field`, `fieldKey`, `value`, `update`, `error`, `mode`, and `disabled`.

## Props

| Prop | Purpose |
| --- | --- |
| `model` | Generated model registry name. |
| `id` | Primary key for edit mode. |
| `initialValues` | Initial create values, including required hidden values. |
| `labels` | Replace generated field labels. |
| `hideFields` | Hide fields from automatic rendering. |
| `store` | Use shared Pinia state. |
| `validate` | Add small synchronous or async application validation rules. |

Untouched database defaults are omitted rather than recreated in JavaScript. Readonly and server-only fields never enter automatic mutation payloads. JSON and arrays use a conservative validated text fallback.
