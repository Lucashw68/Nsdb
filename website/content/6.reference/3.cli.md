The package exposes the `nsdb` executable.

## Commands

| Command | Purpose |
| --- | --- |
| `nsdb init` | Create configuration, folders, environment example, and package scripts. |
| `nsdb generate:types` | Generate Supabase database types. |
| `nsdb generate:metadata` | Introspect deterministic PostgreSQL metadata when DB access exists. |
| `nsdb generate:enums` | Generate schema enum values. |
| `nsdb generate:schemas` | Generate per-table client metadata. |
| `nsdb generate:models` | Generate thin typed table bindings. |
| `nsdb generate:stores` | Generate optional Pinia declarations. |
| `nsdb generate:composables` | Generate the generic model registry. |
| `nsdb generate:all` | Run every generation step in dependency order. |
| `nsdb clear` | Remove only owned generated files. |

```bash
npx nsdb --help
npx nsdb generate:all
npx nsdb clear --dry-run
```

## Initialization options

```bash
npx nsdb init --linked
npx nsdb init --schema private
npx nsdb init --project-id your-project-id
npx nsdb init --self-hosted
npx nsdb init --db-url postgresql://postgres:password@localhost:5432/postgres
npx nsdb init --remote-types
npx nsdb init --force
```

Remote values can also be passed with `--remote-ssh-host`, `--remote-project-path`, and `--remote-db-url`.

Existing initialization files are not overwritten unless explicitly requested. Cleanup has a dry-run and only targets files carrying an NSDB ownership marker or present in the generated manifest.
