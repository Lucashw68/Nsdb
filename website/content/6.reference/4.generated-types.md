---
title: Generated Types
description: Keep database rows, inserts, and updates distinct at the component boundary.
---

Supabase generates different shapes for rows, inserts, and updates. NSDB preserves that distinction in each generated model.

```ts
export type ExampleTableRow = Omit<Tables<'exampleTable'>, never>
export type ExampleTableInsert = Omit<
  TablesInsert<'exampleTable'>,
  'created_at' | 'id' | 'updated_at'
>
export type ExampleTableUpdate = Omit<
  TablesUpdate<'exampleTable'>,
  'created_at' | 'id' | 'updated_at'
>
```

The exact omitted keys depend on PostgreSQL metadata and column exposure.

## Why three types

- `Row` describes values returned by Supabase, including server-generated fields.
- `Insert` describes legal create payloads. Required non-default columns remain required.
- `Update` describes legal partial update payloads.

```ts
const row: ExampleTableRow | null = await exampleTable.getById(id)

const input: ExampleTableInsert = {
  title: 'First entry',
}

const patch: ExampleTableUpdate = {
  title: 'Updated entry',
}
```

Generated model hooks follow deterministic table naming: `exampleTable` becomes `useExampleTable`, `user_profiles` becomes `useUserProfiles`, and `api_keys` becomes `useApiKeys`.

Readonly, generated, identity, and `serverOnly` columns are kept out of mutation shapes rather than weakened to `any`.
