---
title: Queries
description: Filter, search, order, paginate, and include relations with one readable options object.
---

`fetch()` and `refresh()` accept the same canonical query object:

```ts
await exampleTable.fetch({
  where: {
    active: true,
  },
  search: 'rock',
  searchColumns: ['title'],
  orderBy: 'created_at',
  orderDirection: 'desc',
  limit: 20,
  offset: 0,
  include: ['owner'],
})
```

## Query properties

| Property | Purpose |
| --- | --- |
| `where` | Column filters. Primitives imply equality. |
| `search` | Text passed to an `ilike` search. |
| `searchColumns` | Exposed columns searched by `search`. |
| `orderBy` | Column or relation path to sort. |
| `orderDirection` | `'asc'` or `'desc'`. |
| `limit` | Maximum number of rows. |
| `offset` | Starting row offset. |
| `include` | Generated relation aliases to embed. |

## Filter operators

```ts
await exampleTable.fetch({
  where: {
    provider: { op: 'in', value: ['spotify', 'local'] },
    created_at: { op: 'gte', value: '2026-01-01' },
  },
})
```

Supported operators are `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `ilike`, and `in`.

## Advanced options

<ApiBadge>Advanced</ApiBadge>

- `select` exposes raw PostgREST select syntax.
- `orderForeignTable` targets an embedded relation when sorting.
- `merge: true` explicitly accumulates rows rather than replacing the collection.
- `staleTimeMs` overrides the store cache TTL for one request.

Prefer `include` for generated relations and keep raw PostgREST syntax for cases the generated relation catalog does not cover.
