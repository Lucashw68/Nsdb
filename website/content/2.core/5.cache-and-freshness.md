---
title: Cache and Freshness
description: Understand fetch, refresh, invalidate, and the visible stale state.
---

NSDB keeps one visible collection per direct handle or Pinia store.

```ts
await exampleTable.fetch()
await exampleTable.refresh()
exampleTable.invalidate()
```

## Fetch

In direct mode, `fetch()` always queries Supabase. In store mode, it may restore the snapshot for the exact normalized query while that snapshot is still fresh.

## Refresh

`refresh()` queries Supabase now. When called without options, it uses the current query.

## Invalidate

`invalidate()` keeps identity-safe rows visible, clears cached query snapshots, and marks the collection stale. It does not immediately start a request.

```ts
exampleTable.invalidate()

if (exampleTable.stale.value) {
  await exampleTable.refresh()
}
```

Results replace the visible collection by default. Use `merge: true` only when you deliberately want to accumulate pages or items.

## Mutations and complex views

Server-confirmed mutations update simple current collections locally. Filtered, related, or offset collections remain visible but become stale when NSDB cannot safely infer whether a changed row still belongs in the result.

NSDB does not evaluate arbitrary PostgREST filters in the browser or infer dependencies between models. Invalidate another affected model explicitly when application business logic requires it.
