---
title: Realtime
description: Opt in to identity-bound Supabase Realtime and close it explicitly.
---

Realtime is optional and client-only.

```ts
const exampleTable = useExampleTable({ store: true })

await exampleTable.fetch()
exampleTable.subscribe()
```

Stop the channel when the feature no longer needs updates:

```ts
await exampleTable.unsubscribe()
```

Both operations are idempotent. No channel is opened during SSR.

## Event behavior

- `INSERT` deduplicates and adds a row for simple collections.
- `UPDATE` replaces the matching row by primary key.
- `DELETE` removes a known matching key.
- Complex or filtered collections become stale instead of being re-evaluated locally.
- Reconnect invalidates and refreshes the current query to cover missed events.

Subscriptions are bound to the current Supabase identity. An identity change closes the previous channel before clearing rows, and an explicitly requested store subscription may reopen in the new scope.

::callout{type="warning" title="Authorization"}
Realtime does not weaken the rule: RLS remains the authorization boundary. Configure and test Supabase Realtime policies for anonymous users and every authenticated role.
::

For transport and policy details, use the [Supabase Realtime documentation](https://supabase.com/docs/guides/realtime).
