---
title: Direct vs Store
description: Choose independent network-backed handles or explicit shared Pinia state.
---

Store mode is always an explicit choice at the call site.

```ts
const directExampleTable = useExampleTable()
const sharedExampleTable = useExampleTable({ store: true })
```

| Behavior | Direct | Store |
| --- | --- | --- |
| `fetch()` | Always contacts Supabase | May reuse an exact fresh query snapshot |
| Instances | Independent | Shared through Pinia |
| Mutation updates | Current handle | All consumers of the store |
| Cache and TTL | None | Bounded exact-query snapshots |
| Persistence | No | Optional and identity-scoped |
| Realtime | Opt-in per handle | Opt-in shared channel |

## Choose direct mode when

- the data is local to one component or flow;
- every read should contact Supabase;
- shared cache behavior would add no value.

## Choose store mode when

- several components display or mutate the same table;
- returning to a view should reuse a fresh snapshot;
- a list and form should share server-confirmed mutations;
- you need optional identity-safe persistence.

```vue
<NsdbList model="exampleTable" store />
<NsdbForm model="exampleTable" store />
```

Both components resolve the same Pinia collection in this example.

::callout{type="note" title="Module option vs model mode"}
The Nuxt `withStores` option only controls auto-import of advanced store factories. It never changes a model handle to store mode implicitly.
::
