---
title: Generation
description: Generate deterministic types, metadata, schemas, models, stores, and composables.
---

Run all generators after changing the Supabase schema or NSDB exposure configuration:

```bash
npx nsdb generate:all
```

## Generated artifacts

| Artifact | Default output | Value |
| --- | --- | --- |
| Database types | `types/database.types.ts` | Supabase `Row`, `Insert`, and `Update` types. |
| Metadata | `nsdb/database.metadata.json` | PostgreSQL keys, defaults, constraints, and relations. |
| Enums | `nsdb/enums.ts` | Stable schema enum values. |
| Schemas | `nsdb/schemas/` | Client-safe UI and query metadata. |
| Models | `nsdb/models/` | Thin typed table bindings. |
| Stores | `stores/` | Optional Pinia declarations. |
| Registry | `nsdb/composables/useNsdbModels.ts` | Model lookup used by generic components. |

Generated models remain thin. Query, CRUD, cache, and realtime behavior lives in the package runtime instead of being duplicated per table.

## Exact PostgreSQL introspection

When `supabase.dbUrl` or `SUPABASE_DB_URL` is available, the metadata step queries `pg_catalog` for primary keys, SQL defaults, nullability, identity/generated columns, constraints, and relations.

Without direct database access, generation warns and uses the generated TypeScript types as a compatibility fallback. That fallback cannot recover every SQL semantic.

::callout{type="tip" title="Deterministic output"}
Running `generate:all` twice with the same input produces byte-identical files. Generated output contains no timestamps or machine-specific absolute paths.
::

## Safe cleanup

```bash
npx nsdb clear --dry-run
npx nsdb clear
```

Cleanup only removes files proven to be NSDB-generated through ownership markers or the manifest. Unmarked user files are preserved.
