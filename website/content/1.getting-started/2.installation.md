title: Installation
description: Install the RC and its validated Nuxt, Vue, Supabase, and optional Pinia peers.
---

NSDB `1.0.0-rc.1` requires Node.js `>=22.14.0`. The validated peer ranges come directly from the package contract:

| Package | Supported range | Required |
| --- | --- | --- |
| Nuxt | `^4.2.1` | Yes |
| Vue | `^3.5.24` | Yes |
| `@nuxtjs/supabase` | `^1.6.1 \|\| ^2.0.0` | Yes |
| `@pinia/nuxt` | `^0.11.2` | Yes for generated stores |
| Pinia | `^3.0.3` | Yes for generated stores |
| `pinia-plugin-persistedstate` | `^4.5.0` | Optional |

## Install dependencies

::code-group
```bash [npm]
npm install @lucashw68/nsdb @nuxtjs/supabase @pinia/nuxt pinia
npm install --save-dev supabase
```

```bash [pnpm]
pnpm add @lucashw68/nsdb @nuxtjs/supabase @pinia/nuxt pinia
pnpm add --save-dev supabase
```

```bash [yarn]
yarn add @lucashw68/nsdb @nuxtjs/supabase @pinia/nuxt pinia
yarn add --dev supabase
```
::

The Supabase CLI generates database types. Pinia is installed because generation emits optional stores, but a model only uses shared store state when you request it.

## Register the modules

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@lucashw68/nsdb',
    '@pinia/nuxt',
    '@nuxtjs/supabase',
  ],
})
```

For persisted stores, also install `pinia-plugin-persistedstate` and add `pinia-plugin-persistedstate/nuxt` to the module list. Persistence is opt-in and must remain identity-scoped.

## Configure Supabase

Use the public URL and anon key expected by `@nuxtjs/supabase`:

```bash [.env]
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-anon-key
SUPABASE_PROJECT_ID=your-project-id
```

Never place a service-role key in browser configuration, generated files, or the repository.
