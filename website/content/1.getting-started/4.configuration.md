---
title: Configuration
description: Configure the Nuxt module and the NSDB generator without duplicating database rules.
---

NSDB has two configuration surfaces: Nuxt module options for runtime registration and `nsdb.config.ts` for generation.

## Nuxt module options

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lucashw68/nsdb', '@pinia/nuxt', '@nuxtjs/supabase'],
  nsdb: {
    withComponents: true,
    componentsPrefix: 'Nsdb',
    withStores: true,
    autoImportModels: true,
  },
})
```

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `withComponents` | `boolean` | `true` | Register `NsdbList` and `NsdbForm`. |
| `componentsPrefix` | `string` | `'Nsdb'` | Prefix globally registered component names. |
| `withStores` | `boolean` | `true` | Auto-import advanced store factories. It does not enable store mode implicitly. |
| `autoImportModels` | `boolean` | `true` | Auto-import generated `use<Table>()` hooks. |

If a generated hook collides with an application composable, Nuxt fails with an actionable error. Set `autoImportModels: false` and import the generated model explicitly.

## Generator configuration

```ts [nsdb.config.ts]
import type { NsdbConfig } from '@lucashw68/nsdb/types/config'

export default {
  supabase: {
    schema: 'public',
    projectId: process.env.SUPABASE_PROJECT_ID,
    dbUrl: process.env.SUPABASE_DB_URL,
  },
  tables: {
    include: ['exampleTable', 'tracks'],
    columns: {
      exampleTable: {
        internal_note: { serverOnly: true },
        created_at: { editable: false },
      },
    },
  },
} satisfies NsdbConfig
```

See the complete [configuration reference](/docs/reference/configuration) for paths, remote generation, templates, and defaults.
